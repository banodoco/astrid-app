# Regenerating the browser motion pack

RN-5b-min uses the Agent's single deterministic motion projection (not a raw checkout or a fork). Generate it with `scripts/project_astrid_motion.py` in the Agent checkout; keep the output outside any collection. Use that same output for the manual `astrid packs add` proof and browser generation.

With the Agent environment available:

```sh
node scripts/astrid-landing/refresh-motion-projection.mjs --projection /tmp/astrid-motion-source/astrid_motion --agent-repo /path/to/agent --destination /tmp/generated-browser-vendor
```

The command verifies the existing source vendor and the exact pack, generates motion descriptors via the Agent product catalog algorithm, and writes a **new** destination, preserving non-motion source files. Compare the generated directory with `vendor/astrid-browser` and copy the generated bytes and provenance together. For a full vendor refresh, pass `--motion-projection` and `--motion-tool-repo` to `refresh-vendor.mjs`; it refuses to silently reintroduce the raw upstream motion source.

`astrid_commit` and `editor_pack_revisions.astrid_motion` remain upstream provenance; the additive `astrid_motion_tree` field is the verified tree digest. The generated catalog carries separate per-element content identities. Do not use the pack-tree digest as an element revision. No release manifest or installer behavior changes here.

Verify: `node scripts/build/verify-astrid-vendor-sources.mjs`, `node --test scripts/astrid-landing/motion-projection.test.mjs`, and the App build and render-router focused tests. The installed pack-add/clean-host/editor-authored render proof is lane-owned.
