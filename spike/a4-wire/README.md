# A4 wire tap feasibility spike (diagnostic, not a release check)

Base App `e72d541de1d65bee74707ca1ae9c2d429ee2f721`. Nothing here replaces TokenSniff, modifies product paths, or changes CI. Captures stay in memory and output consists only of fixed labels/booleans. Use synthetic data only.

## Source topology and coverage

The Direct harness serves a production build from a hosted-style TLS origin mapped to loopback, with a pinned SPKI and public address-space override. The hosted server answers `/api/*` with 404; the configured runtime and bridge bases target the browser door directly at `http://127.0.0.1:17340/api/runtime` and `/api/astrid`. Chromium explicitly uses `--no-proxy-server`; a conventional environment proxy will not be used. The test grants local-network permission; the door owns Origin/CORS/PNA behavior. Client GETs often use `no-store`; `page.route('**/*')` in TokenSniff disables HTTP cache. Browser defaults and request options control credentials; a relay must preserve Host, Origin, cookies, raw headers and bytes and must not make new CORS/PNA decisions. The operation host has a separate same-origin, credentials-omit, redirect-error transport. TokenSniff scans URLs, initial headers, postData and allHeaders for **all** browser requests; it scans qualifying text/JSON `/api/` responses independent of destination and requires actual terminal events for API admissions, plus DOM, storage, cookie and outbox snapshots. Redirects can introduce further destinations. Limiting a tap to either door prefix alone does not cover that scope.

Existing journey routes can fallback, continue with a changed URL, fulfill a synthetic response, or use `route.fetch()` and fulfill from that response. Such requests can have no corresponding browser-to-door stream or can have an additional non-browser fetch. A relay must not infer a browser request's disposition from the absence of a server hit, nor assume a one-to-one match based on URL and method (duplicates, redirects, retries, concurrency and route handlers make this ambiguous). Interposing on the fixed door port also needs moving the real listener; the presented probe uses disposable ports, not the real Runtime. Changing origin or port changes security and cookie semantics. No existing gate is modified.

## Prototype and decision boundary

`tap.cjs` is a raw TCP relay with capture of bytes at each side, followed by a deliberately narrow single-message HTTP/1.1 framing parser. The parser rejects ambiguous framing, chunks, missing response lengths, truncation and extra/pipelined data. It does not support production HTTP traffic and is not a scanner or correlation mechanism. The prototype's upstream capture shows bytes received from the server; a socket write to the browser does not establish browser receipt or page visibility. A browser cancellation can close the upstream stream, so a server's attempted later writes need not reach the relay. Holding the upstream connection after downstream cancellation would change the network behavior and still would not prove page receipt. Genuine browser request terminals and full browser captures remain independently required. Raw bytes may contain secrets; do not save them or use this fixture against real services.

`probe.cjs` creates temporary self-signed TLS and HTTP endpoints and invokes an installed local Playwright/Chromium. Run only with the host-test lease: `node spike/a4-wire/probe.cjs`. It uses synthetic fixed sentinels, tests a navigation-held response and actual pagehide, a blocked request, redirect, truncation, body and headers. A failure or unsupported cookie policy is inconclusive. The fixture is not an exact release journey or qualification.

No successful browser-wire correlation, route-fulfill coverage, or complete terminal mechanism is asserted. A wire tap can supplement a scan, but server-side absence cannot replace the existing fail-closed check; server-sent bytes are not interchangeable with page-received bytes. Any proposed release mechanism needs explicit owner decision and its own proof preserving the existing requirements.
